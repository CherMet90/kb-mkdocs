# iperf

## Основы

`iperf` — семейство утилит активного измерения пропускной способности IP-каналов (TCP/UDP/SCTP). В отличие от пассивного мониторинга (netflow, zabbix), замер **активный**: трафик генерируется самим инструментом между двумя контролируемыми хостами.

Активно развиваются две независимые ветки:

| Ветка | Автор | Особенности |
|---|---|---|
| iperf3 | ESnet | одиночный поток по умолчанию; Windows официально не поддерживается |
| iperf2 | Broadcom | многопоточный, шире платформенная поддержка (в т.ч. Windows) |

Далее рассматривается **iperf3** как наиболее распространённый. Тест всегда идёт между двумя сторонами: **сервер** (`iperf3 -s`) слушает порт 5201, **клиент** (`iperf3 -c <host>`) устанавливает соединение и гонит данные.

Соединение состоит из двух частей:

- **control-соединение** (TCP 5201) — обмен параметрами теста, старт/стоп, передача итогов;
- **data-поток** — отдельный TCP-поток, набор UDP-пакетов или SCTP-ассоциация.

```mermaid
flowchart LR
    C[Клиент] -->|"control (TCP 5201)"| S[Сервер]
    C -->|"data: TCP/UDP/SCTP"| S
```

По умолчанию данные идут от клиента к серверу (меряется **upload** клиента). Направление задаётся флагами:

| Флаг | Направление |
|---|---|
| _(нет)_ | клиент → сервер (upload) |
| `-R` | сервер → клиент (download, «качать») |
| `--bidir` | одновременно в обе стороны (iperf3 ≥ 3.7) |

### Ограничение скорости `-b`

`-b n[KMGT]` задаёт целевой bitrate. Для TCP по умолчанию не ограничен, для UDP — 1 Мбит/с. Лимит применяется **на каждый поток** отдельно (флаг `-P`). Это позволяет проверить, что канал тянет заданную скорость, **не забивая его полностью** — достаточно держать `-b` чуть ниже ожидаемой ёмкости. На не-Linux реализован внутренним rate control iperf3.

### Ключевые флаги

| Флаг | Назначение |
|---|---|
| `-s` / `-c host` | режим сервера / клиента |
| `-p N` | порт (по умолчанию 5201) |
| `-t N` | длительность теста, сек |
| `-i N` | интервал отчёта, сек |
| `-O N` | пропустить первые N сек (TCP slow start) из итога |
| `-f m` | вывод в Мбит/с |
| `-P N` | N параллельных потоков |
| `-u` | UDP вместо TCP |
| `-J` | вывод в JSON |
| `-B addr` | привязка к конкретному адресу/интерфейсу |

## Установка

Linux (Ubuntu):

```bash
sudo apt update && sudo apt install -y iperf3
iperf3 --version
```

Windows — официальной сборки от ESnet нет, используем поддерживаемую стороннюю (ar51an, актуальная 3.22):

```powershell
winget install -e --id ar51an.iPerf3
# новая сессия PowerShell — exe кладётся в %LOCALAPPDATA%\Microsoft\WinGet\Links
iperf3 --version
```

**Важно:** старые Cygwin-сборки (например 3.1.3) для тестов пригодны, но не поддерживают `--bidir` и имеют лишний оверхед. По FAQ ESnet: «in Cygwin... not all options will work».

## Пример проверки

**Задача:** убедиться, что между двумя хостами в разных локациях стабильно проходит ~10 Мбит/с, не забивая канал.

### Подготовка порта

Сервер слушает TCP 5201. Проверить доступность с клиента.

Linux:

```bash
nc -zv 10.0.1.10 5201
```

Windows:

```powershell
Test-NetConnection 10.0.1.10 -Port 5201
```

Открыть порт на серверной стороне:

```bash
sudo ufw allow 5201/tcp     # для UDP-теста дополнительно: sudo ufw allow 5201/udp
```

### Запуск сервера

```bash
iperf3 -s -p 5201
# обслужить одного клиента и выйти:
iperf3 -s -1
```

### Тест с клиента

Download — сервер отдаёт, клиент принимает, не более 10 Мбит/с, 30 сек:

```bash
iperf3 -c 10.0.1.10 -p 5201 -R -b 10M -t 30 -O 3 -f m -i 1
```

Upload — клиент → сервер:

```bash
iperf3 -c 10.0.1.10 -p 5201 -b 10M -t 30 -O 3 -f m -i 1
```

На Windows команда идентична (`iperf3` или `.\iperf3.exe`).

### Чтение результата

```text
[  5]   0.00-30.00  sec  35.9 MBytes  10.0 Mbits/sec    0   sender
[  5]   0.00-30.00  sec  35.9 MBytes  10.0 Mbits/sec        receiver
```

- `sender` и `receiver` ≈ 10.0–10.1 Мбит/с — заданная скорость держится, цель достигнута.
- Колонка `Retr` (повторы TCP): единицы — норма для WAN; десятки при 10 Мбит/с — потери на пути.

### Проверка потерь через UDP

```bash
iperf3 -c 10.0.1.10 -p 5201 -u -b 10M -t 20 -f m
```

Смотреть `Lost/Total Datagrams` и `Jitter` — при `-b 10M` потерь быть почти не должно.

**Ограничение:** Прогон «с запасом» (`-b` выше ёмкости канала) забивает линк — делать коротким (`-t 5`) и в нерабочее время.

### Типичные проблемы

| Симптом | Причина | Действие |
|---|---|---|
| `Connection refused` | порт закрыт / сервер не запущен | `nc -zv` / `Test-NetConnection`, `iperf3 -s` на сервере |
| `control socket has closed unexpectedly` | несовместимость версий клиента и сервера | привести обе стороны к одной версии (3.22) |
| `the server is busy running a test` | на сервере висит другой тест | `sudo pkill iperf3` |
| `receiver` заметно ниже `sender` при `-b 10M` | потери / Wi-Fi / антивирус | `mtr`, `Get-NetAdapter`, отключить сетевой фильтр AV |
